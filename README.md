# Debug Overlay — Self-Introspection Demo (educational)

A complete, buildable Android app that teaches how memory introspection and
IL2CPP-style metadata parsing work — **entirely inside one app's own process**.

The app embeds a tiny simulated "game" (a mining/idle economy: player,
vehicles, ore veins, workers, coins) and then treats it the way a memory
reader treats a target: it parses `/proc/self/maps`, signature-scans the heap,
validates a checksummed envelope, recovers field offsets from an IL2CPP-format
metadata blob, and streams the live values into an ImGui panel rendered with
OpenGL ES 3.0.

Nothing in this project reads another app's memory, injects into anything,
hooks anything, or writes to memory. Those capabilities are simply not needed
to learn any of the concepts above — and they are what turns this kind of
code from a lesson into a cheat tool. The repo's `dump.cs` (an Il2CppDumper
upload of a commercial game) is **not used anywhere** in this project and
should not be, unless you own the game.

## What you can learn from it, file by file

| Concept | Where | Notes |
|---|---|---|
| `/proc/<pid>/maps` parsing (regions, perms, anonymous vs file-backed) | `app/src/main/cpp/memory.h` | typed region model + lookup helpers |
| Bounds-checked reads (`SafeRead`) | `memory.h` | never dereference without proving the mapping exists |
| Signature scanning + two-stage validation | `memory.h` (`ScanForPattern`), `overlay.cpp` (`Introspection::Rescan`) | pattern hit → structural check → **liveness** check |
| Torn-read detection | `demo_game.h/cpp` (checksum envelope), `overlay.cpp` (`TrySnapshot`) | lock-free reader vs 10 Hz tick thread |
| IL2CPP metadata format (v24.x) | `app/src/main/cpp/il2cpp_demo.h` | builds a real-layout blob, then parses it: sanity `0xFAB11BAF`, string table, `Il2CppTypeDefinition`, `Il2CppFieldDefinition` |
| Field-offset resolution → address composition | `overlay.cpp` (`ObjectAddress` / `FieldAddress`) | `root + GameRoot.economy + Economy.coins` — all offsets from metadata |
| Overlay window management (Android) | `DebugService.java` | `TYPE_APPLICATION_OVERLAY`, foreground service, touch routing |
| 30dp draggable floating button | `DebugService.java` (`PickaxeView`) | tap vs drag discrimination, edge clamping |
| EGL + OpenGL ES 3 + ImGui | `overlay.cpp`, `imgui/`, `imgui_impl/` | RGBA8888 config for the glass look, GLES3 context, ImGui 1.90.4 |
| JNI both directions | `native-lib.cpp`, `NativeBridge.java` | `RegisterNatives`, up-calls via `AttachCurrentThread` |
| JSON settings persistence | `DebugService.java` | `org.json` → `filesDir/settings.json`, debounced atomic writes |
| Dark-glass UI, `#00D4FF` accent, 6 tabs, custom toggle switches | `overlay.cpp` | Player / Vehicles / Ore / Workers / Economy / Misc |

The **Misc** tab is the engine room: live maps viewer, parsed metadata tree,
scan/snapshot diagnostics, `process_vm_readv(self)` smoke test, and the
automatic "metadata ↔ compiled structs" layout validation.

## Build & run

Requirements:

- Android Studio (Hedgehog or newer) with **SDK 34**, **NDK r26+**, **CMake 3.22.1**
  (all installable via SDK Manager → SDK Tools)
- JDK 17 (bundled with recent Android Studio)
- A device or emulator on API 24+

Steps:

1. Open this folder in Android Studio (it contains `settings.gradle`, so it
   imports as a project). Let Gradle sync — ImGui is vendored under
   `app/src/main/cpp/imgui`, so no other downloads are needed beyond the SDK.
2. Build and run the `app` configuration on your device.
3. On the launcher screen: tap **Grant overlay permission** (opens the exact
   settings page), then **Start demo overlay**.
4. You'll see a small cyan **pickaxe button** floating on screen. Drag it
   anywhere; tap it to open the ImGui panel. Tap again (or use the panel's
   `x`) to close.

Command-line build (once Gradle's wrapper is generated by Studio):
`./gradlew :app:assembleDebug`

### Verifying the core on a desktop Linux box

The whole introspection pipeline (maps parsing → scan → checksum →
metadata-driven reads) is plain C++ and ships with a test harness:

```bash
g++ -std=c++17 -O1 -pthread -Iapp/src/main/cpp \
    tools/host_test/main.cpp app/src/main/cpp/demo_game.cpp -o /tmp/host_test
/tmp/host_test
```

It asserts that the scanner finds the live object, that metadata-resolved
addresses match the actual compiled fields, that corrupted metadata is
rejected, and that SafeRead refuses unmapped addresses.

## The end-to-end introspection lesson

1. **Where may I read?** `/proc/self/maps` → `MemoryRegion` records. Only
   readable mappings are ever touched; `SafeRead` clips at region boundaries.
2. **Finding the object.** The game root is a plain POD struct in the heap
   bracketed by a magic header/footer + FNV-1a checksum. The scanner walks
   writable private regions at alignment 8 looking for the 4-byte magic.
3. **Not being fooled.** Every magic hit must validate structurally
   (version, size, footer, checksum) **and** be *live*: the real object's
   checksum keeps changing as the tick thread runs; stale byte-copies (old
   snapshots left on thread stacks) don't. This kills false positives that
   trip up naive scanners.
4. **What is the object?** An IL2CPP-format metadata blob (magic
   `0xFAB11BAF`, version 24) is parsed: string table → type definitions →
   field definitions → per-field offsets. At startup the parser's offsets are
   cross-checked against the compiled structs via `offsetof` — the same
   "does my dump match this binary?" check you'd do manually with a real
   game, automated.
5. **Reading values.** `coins` is read at
   `root + GameRoot.economy + Economy.coins`, all offsets from metadata,
   through bounds-checked `SafeRead`, with checksum-validated snapshots so a
   tick racing the reader can never serve half-written garbage to the UI.
6. **Changing values.** The panel's toggles and sliders call the game's own
   API functions — the way a debug menu works. The overlay never writes to
   memory; introspection stays read-only by design.

## Deliberate scope limits (please read)

- **Self-introspection only.** Reading another app's memory requires
  privileges a normal app doesn't have (root/ptrace) and is the core
  mechanism of game-cheating tools. Not included, not wired up, not
  "leave a blank to fill in".
- No injection, no hooks, no memory writes, no anti-detection, nothing
  targeting a specific shipped game. `dump.cs` in the repo root is unrelated
  to this app and unused by it.
- If you want to go deeper legitimately: build **your own** IL2CPP test app,
  study the format with public research tools (Il2CppDumper, Il2CppInspector)
  on builds you own, read `proc(5)`, `ptrace(2)`, `process_vm_readv(2)`, and
  Unity's `il2cpp` runtime headers. Everything in this repo is a safe
  sandbox for that.

## Troubleshooting

- **"Failed to sync / NDK not configured"** — install NDK + CMake via
  SDK Manager (SDK Tools tab), versions r26+ / 3.22.1.
- **Panel never appears** — the overlay permission was not granted
  (`adb shell appops get com.example.debugoverlay SYSTEM_ALERT_WINDOW`).
- **Black panel instead of glass** — your GPU/emu lacks RGBA8888 window
  configs; try a physical device.
- **Engine stuck in "scanning"** — press *force rescan* in Misc; the scanner
  re-validates with a liveness window (~120 ms per candidate), so first lock
  can take a moment.
