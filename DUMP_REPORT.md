### 1.1 Addressing scheme

Every method in the dump carries three addresses, and in this binary **all three are identical**:

```
// RVA: 0xD9B8F4 Offset: 0xD9B8F4 VA: 0xD9B8F4
private float GetMoveSpeed() { }
```

| Term | Meaning |
|---|---|
| `RVA` | Relative Virtual Address — offset from the start of `libil2cpp.so` |
| `Offset` | File offset inside the `.so` binary (here 1:1 with RVA — no segment remap) |
| `VA` | Virtual Address at runtime |

➡ Practical meaning: **to hook a function in memory, use the RVA as-is** (plus the runtime base address of `libil2cpp.so`). Field offsets (e.g. `// 0x40`) are offsets **inside the C# object** (IL2CPP class layout), used for direct memory reads/writes.

## 2. What Game Is This?

An **idle/mining tycoon mobile game**. The full production loop found in the code:

```
⛏ Mine ore blocks (Pickaxe → Sledge Hammer → Jackhammer → Large Hand Drill)
        ↓  ore pieces drop
🚚 Carry ore (Wooden Carrier → Enhanced Backpack → Exoskeleton Carrier)
        ↓
🏭 Smelter  (SmeltingSpeed, RefiningTime, SmeltingCriticalChance)
        ↓  ingots
💰 Sales Stand  (PriceAmount per ingot)  →  💵 MONEY (ECurrency.Money)
        ↓
📈 Upgrades (StatUpgrade: Attack Power / Attack Interval / Cargo / Move Speed / Fuel…)
🚜 Vehicles (Hydraulic Breaker, Roller Crusher, Drill Crusher, Dump Truck, ATV,
             Haul Truck, Wheel Loader, Bucket Wheel, Fuel Truck, Impact Hauler)
👷 Workers (stamina, cafeteria, hiring)
🧨 Dynamite throws, 🛒 Minecarts, 🌉 Bridges, 🛢 Oil Stations
📺 Ads (Rewarded Video boosts) + 💎 IAP
🗺 World Map / Continents / Stage progression
```

Supporting features in the dump: Onboarding system (~30 tutorial steps), Guide Quests, Secretary Room, Management tree, In-App Shop, Live Ops / World Map events, R&D Center with research timers, AI integration assets (`OpenAI_Settings`, `GeminiGenerateContentRequest` — LLM helper in development).

## 9. Notes & Caveats

1. **RVA = Offset = VA** for this binary — hook addresses can be used directly against `libil2cpp.so` + runtime base.
2. Method bodies are `{ }` stubs — Il2CppDumper emits signatures only; actual logic must be read in a disassembler (Ghidra/IDA) at the listed RVAs.
3. Field offsets come from IL2CPP metadata and are exact for this build; they shift between game updates.
4. The dump mixes **shipping code** (`BulldozerMaster.*`), **asset-store plugins** (Effect Core, ToonyColorsPro, NiceVibrations), **legacy prototypes** (`PlayerController`, `OreNode`, `CameraControl`), and **WIP features** (OpenAI/Gemini settings class, MapTool editor).
5. Save data is plain JSON (Newtonsoft/MiniJSON) via `SaveDataBase` — stats, currency, equipment ownership, mine blocks (`typeId,hp` compact strings) are all client-side.
